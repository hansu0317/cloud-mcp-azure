## 1. 목적·범위

이 문서는 `defineview` 화면정의서 예시의 화면 메타데이터·번호 와이어프레임·항목 설명·Check Point 형식을 CRM AI Notebook에 적용한다. 현재 `/` 단일 페이지에 실제 노출되는 화면과 코드에는 있으나 메뉴에 연결되지 않은 화면을 구분한다.

로그인, 사용자 관리, 관리자 콘솔, 브라우저 라우터, Dataverse 쓰기 화면은 현재 범위에 없다.

| 항목 | 정의 |

| Page Title | CRM AI Notebook 메인 |

## 4. UI-02 프로젝트 사이드바

### 4.1 화면 메타데이터

| 항목 | 정의 |

```text

│ ② 스키마 갱신                │

│ ④ 프로젝트명 입력       ＋   │
│ ⑤ ● 프로젝트 A        전체  │
│    ⑥ 테이블 범위 ＋          │
│    ⑦ 이름 수정  ⑧ 삭제      │
```

### 4.3 항목 정의

| No. | 기능 | 현재 동작 | Check Point |
|---:|---|---|---|
| 1 | 연결 표시 | 환경의 연결 이름과 정적 표시점 | health와 별도임을 안내 |
| 2 | 스키마 갱신 | 기존 카탈로그 테이블을 6개 단위로 갱신 | 새 테이블 자동 발견 기능이 아님 |
| 3 | 섹션 제목 | 프로젝트 목록 영역 식별 | 목록 스크롤에서도 유지 확인 |
| 4 | 생성 | 이름으로 프로젝트 생성 후 테이블 선택 열기 | JSON 파일 생성·활성화 확인 |
| 5 | 전환 | 프로젝트 상세·셀·지침 로드 | 마지막 활성 ID 저장 확인 |
| 6 | 범위 | `UI-03` 열기 | 저장 후 프로젝트 `tables` 반영 |
| 7 | 이름 수정 | inline 편집 후 PATCH | 빈 이름은 기존 이름 유지 |
| 8 | 삭제 | 확인 후 즉시 DELETE | 셀·지침·history도 함께 삭제됨을 안내 |
| 9 | 범위 요약 | 빈 배열은 `전체`, 아니면 `N개` | UI 표기와 서버 저장 일치 |

## 5. UI-03 테이블 선택

### 5.1 화면 메타데이터

| 항목 | 정의 |
|---|---|
| Screen ID | `UI-03` |
| 유형 | Portal modal |
| 데이터 | `/api/tables`의 `name`, `label`, `domain` |
| 목적 | 프로젝트별 LLM 카탈로그와 OData 시작 엔티티 집합 범위 설정 |
| 저장 | `/api/projects/{project_id}` PATCH `{ tables }` |

### 5.2 번호 와이어프레임

```text
┌───────────────────────────────────────────────────┐
│ ① 테이블 선택                                ② × │
│ ③ 검색어 입력                                     │
│ ④ 전체  ⑤ 영업  ⑤ 서비스 ...                     │
│ ⑥ 전체 선택 / 전체 해제       ⑦ 선택 N개          │
├───────────────────────────────────────────────────┤
│ ⑧ □ 거래처      account        [영업]             │
│ ⑧ ☑ 영업기회    opportunity    [영업]             │
├───────────────────────────────────────────────────┤
│ ⑨ 취소                               ⑩ 저장        │
└───────────────────────────────────────────────────┘
```

### 5.3 항목 정의

| No. | 기능 | 규칙 | Check Point |
|---:|---|---|---|
| 1~2 | 제목·닫기 | 닫기/취소는 임시 선택 폐기 | 기존 저장값 유지 |
| 3 | 검색 | 논리명·표시명 기준 필터 | 대소문자·한글 검색 확인 |
| 4~5 | 도메인 | 전체 또는 한 도메인 필터 | 선택 상태는 필터 전환 후 유지 |
| 6 | 일괄 선택 | 현재 설계가 정한 전체 선택/해제 | 선택 수와 행 체크 동기화 |
| 7 | 선택 수 | 현재 임시 선택 개수 | 즉시 갱신 |
| 8 | 테이블 행 | 표시명·논리명·도메인·체크박스 | 중복 없이 토글 |
| 9 | 취소 | 모달 닫기 | 서버 PATCH 없음 |
| 10 | 저장 | 테이블 배열 저장 | 다음 질문부터 서버가 저장 범위를 다시 읽음 |

`tables: []`는 현재 제품에서 “전체 카탈로그” 의미다. “아무 테이블도 허용하지 않음”으로 쓰지 않는다.
서버는 저장 요청의 각 논리 테이블명이 현재 카탈로그에 등록됐는지도 확인하며, 미등록 값은 400으로 거절한다.

## 6. UI-04 프로젝트별 지침

### 6.1 화면 메타데이터

| 항목 | 정의 |
|---|---|
| Screen ID | `UI-04` |
| 탭 | 테이블 관계, 업무 용어, 질문 예시 |
| 데이터 범위 | 활성 프로젝트 한 개 |
| 초안 API | 공통 `GET /api/instructions/draft` |
| 저장 API | `PATCH /api/projects/{project_id}`의 `instructions` |
| 모델 반영 | 다음 질문 때 서버가 저장 지침을 읽어 system prompt에 포함 |

### 6.2 번호 와이어프레임

```text
┌────────────────────────────────────────────────────────────┐
│ ① 프로젝트별 지침      ② 초안 생성                  ③ ×  │
│ ④ 관계(N) │ ⑤ 용어(N) │ ⑥ 질문 예시(N)                   │
├────────────────────────────────────────────────────────────┤
│ ⑦ 탭별 행 편집                                             │
│    관계: from table/column → to table/column/label          │
│    용어: table/column/term/definition                       │
│    예시: question/answer                                    │
│ ⑧ 행 추가 / 행 삭제                                        │
├────────────────────────────────────────────────────────────┤
│ ⑨ 취소                                      ⑩ 저장          │
└────────────────────────────────────────────────────────────┘
```

### 6.3 항목 정의

| No. | 기능 | 규칙 | Check Point |
|---:|---|---|---|
| 1 | 범위 안내 | 현재 프로젝트 전용 | 다른 프로젝트와 섞이지 않음 |
| 2 | 초안 생성 | 활성 `server.<profile>.log` 최근 엔트리에서 용어·성공 질문/답변 후보 생성 | 자동 저장 금지, 사람이 검토 |
| 3 | 닫기 | 편집값 폐기 | 서버 데이터 유지 |
| 4~6 | 탭 | 항목 수와 편집 영역 전환 | 각 배열 독립 유지 |
| 7~8 | 편집 | 행 추가·삭제·입력 | 초안의 빈 table/column/definition 보완 |
| 9 | 취소 | 저장 없이 닫기 | 재개 시 기존 값 복원 |
| 10 | 저장 | 프로젝트 instructions PATCH | 다음 질문에서 서버 권위 지침 사용 |

초안은 Cloud/Local 모두 제공되며 `joins`는 항상 빈 배열이다. 로그 휴리스틱 결과는 사실 검증을 대신하지 않는다.

## 7. UI-05 질문 셀

### 7.1 화면 메타데이터

| 항목 | 정의 |
|---|---|
| Screen ID | `UI-05` |
| 입력 | 자연어 질문 |
| 실행 | 셀 실행 버튼 또는 Shift+Enter |
| API body | `{ message, sessionId }` |
| 출력 | 상태, Markdown 답변, 시간, 도구/OData 기록, 내보내기 |
| 저장 | 셀은 프로젝트 PATCH, LLM history는 서버 chat 경로가 별도 저장 |

### 7.2 번호 와이어프레임

```text
┌────────────────────────────────────────────────────────────┐
│ ① AI  ② In [ ]  ③ 질문 미리보기        ④ 실행  ⑤ 삭제    │
│ ⑥ 질문 입력                                               │
├────────────────────────────────────────────────────────────┤
│ ⑦ 상태: thinking / tool / query / done / error            │
│ ⑧ Markdown 답변                                           │
│ ⑨ 응답시간     ⑩ 실행 쿼리                               │
│ ⑪ CSV/TXT 내보내기                                        │
└────────────────────────────────────────────────────────────┘
```

### 7.3 상태·행동 정의

| 상태 | 표시 | 허용 행동 | 종료 조건 |
|---|---|---|---|
| `idle` | 질문 입력 | 입력·실행·삭제 | 실행 시작 |
| `thinking` | 스피너, `In [*]` | 중복 실행 제한 | 첫 이벤트/완료/오류 |
| `tool` | 도구 이름 | 대기 | 다음 SSE 이벤트 |
| `query` | 도구 입력 기록 | 대기 | 모델 후속 응답 |
| `done` | 답변·시간·쿼리·내보내기 | 재실행·편집·삭제 | 새 실행 |
| `error` | 오류 메시지 | 수정·재실행·삭제 | 새 실행 |

서버는 요청 body의 테이블·지침을 신뢰하지 않는다. 저장된 프로젝트가 없으면 404, LLM 설정이 없으면 503이다. 공급자별 원문 이벤트는 공통 SSE로 변환되므로 셀 UI 계약은 같다.

## 8. UI-06 서버 로그 — 미연결

| 항목 | 정의 |
|---|---|
| Screen ID | `UI-06` |
| 현재 상태 | 컴포넌트는 있으나 GNB/LNB에 진입 메뉴 없음 |

## 10. 알려진 제약

- 사용자 로그인·RBAC·프로젝트 소유권이 없다.
- 정적 연결 표시점은 실시간 health가 아니다.
- `API_KEY` 활성화 시 현 SPA가 헤더를 전송하지 않아 별도 안전한 프록시 없이는 401이 된다.
- 서버 로그 화면은 민감 데이터 보호 설계가 없어 메뉴에 연결하지 않았다.
- 키보드 접근성, 포커스 트랩, 모바일 레이아웃은 전문 접근성 검증을 거치지 않았다.
- 프로젝트 삭제에는 휴지통·복구·버전 이력이 없다.
