SHEET 01

코드 계층 구조 — 누가 무엇을 직접 만지는가

FastAPI는 프로젝트/스키마 JSON을 직접 열지 않고 stores/의 DocumentStore 계약(get/put/delete)만 거친다 — 나중에 실서버 DB로 옮길 때 호출부를 안 고쳐도 되게 하려는 설계다. 빨간 점선이 그 원칙을 깨는(그러나 실제로는 안 쓰는) 지름길이다.

SHEET 02

코드 지도 — 파일별로 뭘 하는지

SHEET 01의 계층이 실제로 어떤 파일들로 쪼개져 있는지. store/(단수)와 stores/(복수)가 둘 다 있는 게 오타가 아니라 — 도메인 규칙과 실제 저장 방식을 의도적으로 분리한 것이다.

SHEET 03

API 엔드포인트 스펙

21개 라우트, 담당 파일별로 묶었다. POST /auth/dev-login은 DEV_FAKE_LOGIN=true일 때만 존재하는 진단용이라 표에서 제외했다(기본은 꺼져 있음). "소유"는 viewer_email 폴더 밖 프로젝트는 존재 자체를 모른다는 뜻.

SHEET 04

흐름 — 로그인부터 노트북 진입까지

Microsoft 인증 자체가 성공해도 data/users.json 화이트리스트에 없으면 세션을 만들지 않는다(2026-08-25, "등록 안 된 사람은 접근 자체를 막아라") — RBAC이 아니라 화이트리스트 게이트다.

SHEET 05

흐름 — 질문 하나가 답이 되기까지 (핵심 루프)

브라우저는 {message, sessionId}만 보낸다 — 테이블 범위·지침은 서버가 프로젝트 파일에서 매번 다시 읽는다(요청 바디 값은 안 믿는 fail-closed 설계). Text-to-SQL이 아니라 Text-to-OData다.

SHEET 06

지침 구조 — 조인·용어·예시가 답변에 반영되는 경로

"지침"은 AI를 다시 학습시키는 게 아니라, 매 질문의 시스템 프롬프트에 자동으로 끼워 넣는 메모다. 세 탭 모두 각자 자기 프로젝트 범위의 후보만 보여주고, 전역 로그 기반 "초안 생성"은 2026-08-21에 없앴다.

SHEET 07

흐름 — 정지 버튼과 좀비 로딩 셀 복구 (2026-08-31)

"질문 보내고 계속 도는데 안 끝난다"는 실사용 신고에서 나온 당일 수정 두 건. 서버 쪽 정리 로직(chat_api.py)은 이미 있었고, 없던 건 프론트가 실제로 끊는 배선이었다.

SHEET 08

LLM 프로필 전환 — Cloud(anthropic) ↔ Local(ollama)

같은 코드, .env의 LLM_PROVIDER 한 줄만 다르다. 단 provider는 프로세스 시작 후 최초 1회만 캐싱되므로 .env를 고쳐도 서버를 재시작해야 반영된다.
